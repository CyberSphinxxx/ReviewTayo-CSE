# Release checklist

The pack's `release/RELEASE-CHECKLIST.md`, answered for this app. Each row names its
evidence or its blocker — nothing here is ticked from optimism. Rows that need a
device, a signing key or a store account are marked **external** and tracked in
`agent/BLOCKERS.md`.

| Item                         | Answer                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Version / build numbers      | `expo.version` is `1.0.0` in `app.json`. The production EAS profile uses `appVersionSource: remote` with `autoIncrement`, so build numbers are assigned by the build service rather than hand-edited.                                                                                                                                                                             |
| Production env               | `EXPO_PUBLIC_APP_ENV=production` is set by the production profile. The only other variables are the optional API base URL and Google client IDs (`.env.example`, README).                                                                                                                                                                                                         |
| No debug endpoints           | The app's single network boundary is `HttpApiTransport`, whose base URL comes from `EXPO_PUBLIC_API_BASE_URL`. Unset means `LocalOnlyTransport`. No URL is hard-coded in `src/` or `app/`.                                                                                                                                                                                        |
| No test credentials          | No secret is committed. The fakes in `tests/setup.ts` are test-only; `.env*.local` is gitignored; `.env.example` holds empty placeholders. The EAS project id in `app.json` is a placeholder and must be replaced by the account owner before a cloud build.                                                                                                                      |
| Icons / splash               | `assets/icon.png`, the Android adaptive icon set (foreground/background/monochrome) and the light/dark splash are configured in `app.json` and resolved by `expo config`.                                                                                                                                                                                                         |
| Permissions                  | Audited with `expo config --type introspect`: the app declares only `INTERNET` (sync, when a backend is configured); reminders contribute `VIBRATE` and `POST_NOTIFICATIONS`; the legacy `READ_EXTERNAL_STORAGE`/`WRITE_EXTERNAL_STORAGE` pair is explicitly blocked with `tools:node="remove"`; `SYSTEM_ALERT_WINDOW` is React Native's debug overlay, not a release permission. |
| Privacy disclosures reviewed | Written down in `docs/play-store.md` (Data safety) and `docs/app-store.md` (App Privacy) from what the code actually stores.                                                                                                                                                                                                                                                      |
| Analytics provider status    | Vendor-neutral interface, default no-op. Nothing is sent anywhere in v1; a provider is an injected implementation, not a build flag.                                                                                                                                                                                                                                              |
| Crash provider status        | Same boundary, same default.                                                                                                                                                                                                                                                                                                                                                      |
| Full tests green             | 49 suites / 723 tests (`npx jest`), plus `tsc`, `eslint` and `prettier` clean; `npx expo export --platform android` green.                                                                                                                                                                                                                                                        |
| E2E green                    | The ten pack journeys exist as Maestro flows in `e2e/` and are mirrored by CI-executable journey suites (D-011). CI runs the mirror; device execution is **external** (no Android SDK here — B-EXT-3).                                                                                                                                                                            |
| Visual QA accepted           | Light/dark composition, type roles, spacing and 28 audited colour pairs are asserted against the tokens; device captures are **external** and tracked in `agent/VISUAL-QA.md`.                                                                                                                                                                                                    |
| Android build verified       | The Hermes bundle export is verified on every gate. A signed APK/AAB needs the Android SDK or EAS signing: **external** (B-EXT-3). The build path is documented in `docs/play-store.md`.                                                                                                                                                                                          |
| iOS config verified          | Bundle id and `ITSAppUsesNonExemptEncryption` resolve correctly and every plugin's plist contribution was reviewed. An archive needs an Apple team: **external**.                                                                                                                                                                                                                 |
| Known limitations            | Four questions per concept in the CSE bank (mastery's `Mastered` floor is five answers); the default build has no backend; five build-chain-only dependency advisories (B-EXT-4).                                                                                                                                                                                                 |
| Rollback / recovery          | The app is local-first: there is no server state to roll back, and a bad release is replaced by shipping a fixed one. Local data survives updates through the versioned migrations, and queued sync events retry with backoff. Nothing destructive is keyed to a release.                                                                                                         |

## The gate, in one command

```bash
cd mobile
npm ci
npm run verify                                   # format + lint + typecheck + tests
npx expo export --platform android               # the bundle really builds
```

CI runs the same commands (`.github/workflows/mobile-quality.yml`).
