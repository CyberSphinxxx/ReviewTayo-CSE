# Clean Code Rules

- descriptive domain names
- no `any` without justification
- no arbitrary utility dumping grounds
- pure functions for calculation-heavy domain logic
- one responsibility per service/module
- avoid premature abstractions
- refactor duplication after the pattern is clear
- feature public APIs should be explicit
- avoid circular imports
- no business logic in render trees
- comments explain why, not obvious what
- tests should describe behavior, not implementation details
